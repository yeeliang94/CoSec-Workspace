## Findings

### P1 — Switching library sections silently discards a new clause

- **Location:** `src/app/templates/page.tsx:52`, creation toggle at line 69; `NewClause` begins at line 450.
- **Category:** Implementation integrity / recovery.
- **Reproduction on port 3001:** Clause library → New clause → enter a name and description → select Assemblies → return to Clauses → New clause.
- **Actual:** No discard confirmation; both fields reopen empty. No draft was created.
- **Expected:** Preserve the unsaved creation form or run the shared discard guard before unmounting it. DESIGN_SPEC.md requires meaningful edits to be retained or guarded before discarding.
- **Cause:** `choose()` changes the section and calls `setCreating(false)` directly. The creation toggle also unmounts directly. A `data-dirty` marker alone does not protect these local handlers.
- **Fix:** Guard section changes and form-closing paths consistently; use meaningful changes across the form to determine dirty state. Include New assembly and New resolution in the follow-up inventory, since their local close handlers use similar patterns; their data loss was not independently reproduced here.
- **Suggested command:** `$impeccable harden`.
- **Evidence:** `.local/ui-qa-2026-10-27/unsaved-before.jpg` and `unsaved-after.jpg`; the latter is the reopened blank form. The name and description were both read back as empty.

### P2 — Supporting routes lose the selected main-navigation item

- **Location:** `src/components/workspace.tsx:213`.
- **Category:** Implementation integrity / navigation orientation.
- **Reproduction:** Open Clause library or a clause editor. The same route-matching limitation applies to People and Audit.
- **Actual:** No main-navigation link has `aria-current`; the template editor on port 3001 returned an empty list of current links.
- **Expected:** Supporting pages retain a clear selected parent in the approved application shell.
- **Fix:** Define route-to-navigation ownership explicitly for `/templates`, `/people` and `/audit`, consistent with the approved information architecture. Do not rely solely on matching each navigation link's pathname prefix.
- **Suggested command:** `$impeccable harden`.
- **Evidence:** `.local/ui-qa-2026-10-27/editor-desktop.jpg`. A hover fill on Billing in that screenshot is pointer position, not a selected route; the DOM confirms that no route is current.

### P2 — Wording tabs omit the expected keyboard interaction

- **Location:** `src/components/resolution/clause-editor.tsx:286`.
- **Category:** Accessibility / component contract.
- **Reproduction on port 3001:** Focus the Directors' written resolution tab and press ArrowRight.
- **Actual:** Focus and selection remain on Directors. Both tabs have `tabIndex=0`; no arrow-key handler is implemented.
- **Expected:** DESIGN_SPEC.md requires a tested accessible tab pattern or simple navigation links. A `tablist` should implement the corresponding focus/selection keyboard pattern.
- **Impact:** Keyboard users encounter tab semantics without the expected navigation. Tab and activation remain available, so this does not block all access.
- **Fix:** Implement roving focus and Left/Right/Home/End handling, or use ordinary navigation controls with appropriate current-state semantics. Verify focus and panel association after switching.
- **Suggested command:** `$impeccable harden`.

### P2 — Template toolbar ignores the Larger text preference

- **Location:** `src/app/globals.css:786` and `src/app/globals.css:2223`.
- **Category:** Accessibility / typography / responsive design.
- **Actual:** With Larger text enabled in the exploratory runtime, toolbar buttons and the style selector remain 12px; buttons remain 30px high. Main-workspace source confirms the same unscaled `font-size: 12px` rules. The final latest-build preference recheck was interrupted, so the runtime observation and source confirmation are distinguished here.
- **Expected:** DESIGN.md requires the personal text-size preference to scale UI typography roles. Document typography belongs to the template, but formatting controls are application UI.
- **Impact:** Users choosing larger UI text still have small formatting controls; mobile authoring requires extra care.
- **Fix:** Scale the toolbar's UI text with the shared preference and let controls reflow. Keep document output typography separate. Review touch sizing as part of this change; a 30px height alone does not establish a WCAG 24px-target failure.
- **Suggested command:** `$impeccable typeset`, then `$impeccable adapt`.
