# Shared implementation contracts

Coordinator owns src/domain/model.ts, src/server/db.ts, schema.ts, repository.ts, auth.ts, http.ts and src/app/api/**. Worker domain owns src/domain/workflows.ts and src/server/workflows.ts plus tests/workflows*. Worker support owns src/server/support.ts, src/server/storage.ts, scripts/worker.ts, tests/support*. Worker UI owns src/app/** except api, src/components/**, src/app/globals.css. Coordinator owns package/config/scripts seed/migrate.

API: GET /api/workspace -> Workspace DTO. POST /api/jobs -> create Job. POST /api/jobs/:id -> mutation {expectedRevision, requestId, action, ...payload}. POST /api/companies -> create; GET /api/companies/:id?asAt=YYYY-MM-DD -> scoped Company + officers. POST /api/documents multipart (companyId,jobId?,file,title) -> Document; GET /api/documents/:id -> private download. POST /api/settings {expectedRevision,requestId,action,...}. POST /api/preferences {textSize,density,reducedMotion}. POST /api/auth/sign-in/email via Better Auth. GET /api/session -> actor; POST sign-out. API errors {error:string,code:string} and HTTP 400/403/404/409. All dates YYYY-MM-DD. Workspace includes actor, companies, jobs, documents, settings, users (safe ids/names), reminders. No unrestricted personal identity evidence.

Repository (coordinator): reads take an optional trailing `tx`; inside a transaction always pass it, so one change never borrows a second pooled connection. getCompany(id), listCompanies(actor), listJobs(actor), getJob(actor,id), createJob(actor, job, requestId), mutateJob(actor,id,expectedRevision,requestId, operation:(job,tx)=>Promise<Job>|Job), listOfficerEvents(companyId,tx?), insertOfficerEvent(event,tx), getSettings(), mutateSettings(actor,expectedRevision,requestId,fn), listDocuments(actor), getDocument(actor,id), getDocuments(actor,ids) one query for many, insertDocument(actor,doc), audit(actor,companyId,action,subjectId,detail,tx?), listUsers() safe active users, listReminders(actor), reconcileCompanyReminders(companyId,tx?) under the company lock (also called by createJob/mutateJob). Idempotency stores a small receipt; a replay returns the subject's current state. assertCapability(actor,cap), assertCompany(actor,companyId,cap?) exported from access.ts. All mutation callbacks run under transaction and row lock; repository supplies audit/idempotency. Request ID scoped by actor/operation. createJob checks unique company/year W03. Job data itself includes immutable versions/histories.

Domain worker export createJobInput Zod schema and createJob(actor,input,requestId), applyJobAction(actor,id,input) from server/workflows.ts, which runs shared guards and dispatches to one handler per action in server/job-actions/ (pack, review, filing, casework; each declares its schema and guard flags). Export pure blockers(job), nextAction(job), officersAt(events,asAt) from domain/workflows.ts. Support worker export getWorkspaceSupport(actor) -> {documents,settings,reminders}; applySettingsAction(actor,input), savePreferences(actor,input), storeUpload(actor,{companyId,jobId?,title,file:File}), readDownload(actor,id)->{document,bytes}, reconcileReminders(), and worker CLI. UI fetches workspace; coordinator routes enrich jobs with blockers and nextAction optional computed props. API mutation returns job then UI refreshes workspace. UI should inspect model before writing payloads and coordinate differences.

## Company register extension

`GET /api/companies/:id/registers?asAt=YYYY-MM-DD` returns the effective member/capital position, immutable certificate history and approved event history. `GET /api/companies/:id/bo?asAt=YYYY-MM-DD` additionally requires `view_bo`, audits access and returns effective BO entries/history. W06 jobs, documents and reminders are filtered by the same capability and company scope. General workflows reject BO evidence even for a privileged reader.

`record-actions.ts` validates W05 proposals and W06 notice/reply/escalation/discrepancy/assessment commands; `record-store.ts` owns transactional register persistence. `company_registers` is company locked, revisioned and updated atomically with job and audit. Every new W05/W06 pack pins its complete record proposal, original reconciliation and register base revision. Posting requires current independent pack/record decisions and execution evidence, validates the complete future ledger and flags affected annual snapshots. Filing remains independent.
